# Enemy ignite checks

`scripts/test-flame-ignite.ps1 -GameDir <game> [-CandidateDll <dll>] [-RunName <name>]` runs a short isolated Unity/PlayMaker fixture. It does not start a world or open personal saves. Input hash, result, timings and logs stay in `artifacts/flame-ignite-<name>`. The existing native result gate requires a fresh passing report, process exit code zero and no native shutdown/crash markers.

## Behavior

October 18 visual follow-up: five capped two-particle sheets at 1.05 m replace three at 0.9 m; DPS, fuel, stacks, deadline and .65 s fade are unchanged. Both direct flame and burn damage retain native Bodypart events. Exact Health corpse CreateObject actions are watched for deaths caused by those events; a guarded transpiler observes the actual created body before native loot can overwrite Item. Unrelated deaths, including later kills after a surviving flame hit, are not scorched. Watches expire after a bounded delayed death or actor teardown and clear on scene cleanup.

Only the resulting corpse's MeshRenderer/SkinnedMeshRenderer material copies change. The native coal atlas's dark left-hand area supplies the charred appearance; glow, gloss and metallic settings are disabled on those copies. A missing texture uses a matte dark tint. Shared materials, shaders, loot, living characters and game assets remain untouched. No extracted texture is distributed. Copies are owned by the corpse and destroyed with it. The effect is scene-local cosmetic state; retaining this new appearance across saving/loading corpses is **NOT VERIFIED** and no new corpse save format was added.

Latest native checks: 59 standalone, 60 with WW 0.1.36's actual CreateObject melee prefix active. They exercise direct/delayed deaths, unrelated deaths, shared Item loot overwrite, template isolation, dark atlas coordinates, missing-resource fallback and cleanup. The original installed build fails four new visual/death assertions. Material-property assertions require Direct3D: the no-graphics host returned a Standard shader stub with no properties, so it could only verify routing, not texture application. The runner now retains graphics and requires clean exit. Actual world appearance, all enemy/ragdoll variants and long-session costs remain live checks. Current isolated 24-actor advance timing is about .10 ms per simulated frame, not a whole-game FPS measurement.

Funded flame contact ignites a living enemy at one stack. Each additional second of observed contact adds a stack, up to five by default. Default damage is 10 DPS per stack, for 10/20/30/40/50 DPS. Contact at the maximum still refreshes the ten-second deadline. Gaps add no contact credit; existing stacks survive until expiry. Settings in `Flamethrower - Ignite` control damage per stack, maximum stacks, stack interval and burn duration.

The stream's final posed, cover-checked geometry is sampled once per funded frame, independently of the direct-damage attack rate. Its contact dictionary is reused by a paid direct-damage tick in the same frame/pose. Repeated render callbacks cannot add another stack charge. Ordinary direct flame damage/cadence is retained. A double contact accumulator avoids losing a stack at a high-frame-rate time boundary.

Burns own scene-local objects and keep working after weapon switching or destruction of the pack's original native plugin component. They use scaled game time, so pause stops damage and expiry. Death, destruction and expiry end damage and shrink/fade the existing fire sheets. Scene cleanup cancels owned statuses and releases the owned material. The visual uses a private copy of the current native fire material, without its damaging triggers, light, sounds or new texture files.

Fixed burn damage uses the living actor's root Bodypart Damage event, never the contacted head/limb receiver or direct Health writes. Native Flexa/Scrud/Sprokka root metadata has FsmFloatAdd without a head FloatMultiply, while their head receivers include the multiplier. Unsupported actors without a root Bodypart/Health contract are left alone. Physical `*_Dead` roots are excluded even if they retain a positive Health variable. Production code has no BloodFX API calls and instantiates no melee blood for flame/burn hits; another mod can still react independently to native health changes.

## Verification, 2026-10-18

The pre-ignite DLL fails the setup negative control. The corrected public DLL passed 38 native checks: real root health damage, all default stack levels/cap, 30/144 FPS four-second ramp, head-multiplier independence, latest-contact expiry, configured values, independent actors, contact gaps, corpse exclusion, actor movement/destruction, death/expiry shrink, pause, stream-stop persistence, actual cone contacts, repeated-render suppression, native damage/cache reuse, retained managed owner and the production scene-cleanup method. An intermediate test caught a float stack-boundary miss at 144 FPS; the corrected accumulator passes. Early diagnostic fixtures used the GameObject ID to look up a Transform-keyed status and were corrected; those failed runs are not passing evidence.

The feature fixture DLL hash was `5F369090FE2D9B06DEFC17F340305DDE62B41B507E2B5009B862D0273B5B912E`; the final merged candidate subsequently passed the same 38 checks (see TESTING.md for its identity). With 24 actual native actor/FSM/collider fixtures, 100 warmed measurements averaged 0.1631 ms for contact collection, 0.1869 ms for collection plus ignite touches and 0.0922 ms for advancing 24 native burns/visuals. These are isolated method timings, not whole-game frame-rate measurements. Timing records are also written separately from buffered BepInEx logs. All native processes in this suite exited normally through the result gate. No full-game process was used.

The preceding integrated public candidate also passed the 43 solid melee/BloodFX checks; the last ignite-only guard then gained a test preventing a refresh from restarting a burn that just killed its target. Public compilation retained six existing warnings and no errors. The matched development source compiled into a private staged directory with twelve existing warnings and no errors. Its new ignite path has not had a separate native run after the final source merge.

Full rendered flame appearance/body coverage, complete enemy variants, moving patrol crews in real generated vehicles, normal game pause/menu transitions, the full mod collection, packaged startup and long-session performance remain live checks. A passing synchronous native fixture does not establish those behaviors. Nothing was installed, published or committed by these checks.
